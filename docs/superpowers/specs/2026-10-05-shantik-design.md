# Шантик — дизайн

Telegram-бот + Telegram Mini App: виртуальный питомец (шпиц Шантик), состояние которого
зависит от выполнения задач. Для людей с СДВГ: настойчиво, но тепло, без наказаний.

Срок рабочей версии: 27.12.2026.

## 1. Цели и ограничения

- Пользователь — один (`USER_ID`), плюс админ (`ADMIN_ID`) для наполнения наград.
  Остальным бот отвечает «Это личный бот 🐾» и больше ничего не делает.
- Про бота нельзя забыть: он сам пишет от лица Шантика.
- Никаких стриков, счётчиков пропусков, болезни или смерти питомца.
- Разработка на Windows, только бесплатные тарифы, интерфейс на русском.
- Репозиторий публичный: личный контент (записки, фото) никогда не попадает в git.

## 2. Механика питомца

### Потребности
Четыре шкалы 0–100, каждая наполняется задачами своей категории:

| Потребность | Задачи | Убывание |
|---|---|---|
| 🍖 Миска (`food`) | забота о себе: еда, вода, таблетки, душ, сон | −7/ч |
| 🦮 Прогулка (`walk`) | движение и дела вне дома | −5/ч |
| 🎾 Игра (`play`) | работа, учёба, быт | −5/ч |
| 🤍 Ласка (`love`) | отдых и приятное для себя | −4/ч |

- Убывание идёт только вне тихих часов.
- Нижний предел шкалы — 10.
- Выполнение задачи: +35 к её потребности (максимум 100), вес у всех задач одинаковый.
- Возвращение после перерыва ≥ 24 ч: первая выполненная задача даёт +70.
- Все числа — в одном объекте конфигурации `src/core/tuning.ts`.

### Состояния (по самой низкой шкале)
| Состояние | Условие |
|---|---|
| `sleeping` | сейчас тихие часы |
| `celebrating` | первые секунды после выполнения задачи (только в Mini App) |
| `asking:<need>` | какая-то шкала < 30; показывается самая низкая |
| `happy` | все шкалы ≥ 60 |
| `ok` | иначе |

### Награды
- 💌 Записка: когда все четыре шкалы ≥ 80, не чаще 1 раза в календарный день.
- 📷 Фото: за каждые 10 выполненных задач (`completed_total % 10 == 0`).
- Выдаётся самая старая неоткрытая награда нужного типа. Если неоткрытых нет — ничего не происходит.
- Полученные награды бот присылает в чат и показывает во вкладке «Сокровища».

## 3. Mini App

Три вкладки внизу:

1. **🐶 Шантик** — SVG-Шантик в текущем состоянии + реплика, 4 шкалы,
   2–3 ближайшие задачи с отметкой выполнения. Шестерёнка → настройки (тихие часы, часовой пояс).
2. **✅ Задачи** — переключатель «Сегодня / Рутины». Кнопка «+»: текст, потребность,
   опционально время (разовая) или время + дни недели (рутина). Тап — изменить, свайп влево — удалить.
3. **🎁 Сокровища** — «Записки» и «Альбом»; закрытые фото показаны замочками с прогрессом «3/10».

### Шантик (графика)
Стиль — плоская kawaii-иллюстрация. Один SVG из деталей (тело, уши, глаза, рот, язык,
щёчки, лапки, предмет-подсказка: миска / поводок / мячик / сердечко). Состояния собираются
заменой деталей, анимации — CSS. Приметы: кремово-белый, рыжие уши и спина,
тёмные глаза-бусинки, чёрный нос, пышная грива, язык наружу в радости.

## 4. Бот

### Входящие
- `/start` — знакомство + кнопка «🐶 Открыть Шантика» (Mini App).
- Любой текст от пользователя → разовая задача на сегодня;
  ответ «Записал: «…» ✍️ Куда засчитаем?» с кнопками 🍖 🦮 🎾 🤍.
  Задача создаётся после выбора потребности.
- Кнопки в напоминаниях: «✅ Сделала», «⏰ Через час» / «⏰ Позже».

### Исходящие (решает `tick`)
| Тип | Когда | В лимите 6/день |
|---|---|---|
| Рутина | в её время, в её дни | нет |
| Сигнал потребности | шкала < 30, не чаще 1 раза в 3 ч на потребность | да |
| Повтор | через 1,5 ч после неотвеченного сигнала, один раз | да |
| Утро | через 30 мин после конца тихих часов | да |
| Вечер | за 1 ч до начала тихих часов | да |
| Награда | сразу при выполнении условия | нет |

- В тихие часы бот ничего не отправляет (рутины, попавшие в тихие часы, не отправляются).
- Сигнал предлагает её открытую задачу с этой потребностью; если таких нет —
  простое действие из встроенного списка.
- На каждую ситуацию 5–10 вариантов фраз (`src/bot/phrases.ts`), выбор случайный.
- Вечер без выполненных задач: «Сегодня был тихий день, это тоже нормально. Я рядом 🤍».

### Админ
- `/note <текст>` — добавить записку.
- Фото с подписью — добавить фото в альбом (хранится `file_id`).
- `/left` — сколько неоткрытых записок и фото осталось.

На время разработки `USER_ID` = Telegram ID разработчика.

## 5. Архитектура

Один проект Vercel (Hobby), база Neon Postgres (free), cron-job.org.

```
web/          Mini App: Vite + React + TypeScript
api/
  bot.ts        webhook Telegram (grammY)
  tick.ts       планировщик, вызывается cron-job.org каждые 10 минут
  app/*.ts      REST для Mini App
src/core/     чистая логика без I/O (шкалы, состояние, награды, решения планировщика)
src/db/       SQL-запросы (@neondatabase/serverless)
src/bot/      обработчики и фразы
```

Зависимости: `grammy`, `@neondatabase/serverless`, `react`, `zod`, `vitest`, `vite`.

### Данные
Один пользователь — без `user_id`.

| Таблица | Поля |
|---|---|
| `settings` (1 строка) | `timezone`, `quiet_start` (`"23:00"`), `quiet_end` (`"09:00"`) |
| `pet` (1 строка) | `food`, `walk`, `play`, `love`, `updated_at`, `last_seen_at`, `completed_total`, `last_note_date` |
| `tasks` | `id`, `title`, `need?`, `due_at?`, `done_at?`, `created_at` |
| `routines` | `id`, `title`, `need`, `time` (`"20:00"`), `days` (битовая маска пн..вс), `active` |
| `routine_log` | `routine_id`, `date`, `sent_at?`, `done_at?`, `snoozed_until?` |
| `outbox_log` | `id`, `kind`, `need?`, `sent_at`, `answered_at?`, `followed_up` |
| `rewards` | `id`, `kind` (`note`/`photo`), `text?`, `file_id?`, `created_at`, `unlocked_at?` |

Задача из чата сначала сохраняется черновиком (`need = null`), id черновика уходит
в `callback_data` кнопок; после выбора потребности черновик становится задачей.
Черновики без потребности не показываются и не учитываются.

### Шкалы
В базе хранятся значения и `updated_at`. Текущие значения считает чистая функция
`decay(needs, from, to, quietHours, timezone)`; её используют и API, и `tick`, поэтому
пропуск запуска cron не ломает расчёт.

### API Mini App
- `GET /api/app/state` — шкалы, состояние, ближайшие задачи.
- `GET/POST/PATCH/DELETE /api/app/tasks`, `/api/app/routines`.
- `GET/PATCH /api/app/settings`.
- `GET /api/app/rewards`, `GET /api/app/photo/:id` (прокси к Telegram, токен не уходит клиенту).
- Входные данные проверяются через `zod`.

### Безопасность
- Webhook: заголовок `X-Telegram-Bot-Api-Secret-Token`.
- `/api/tick`: секрет в заголовке.
- Mini App: проверка подписи `initData` (HMAC от токена бота), `auth_date` не старше 24 ч,
  `user.id ∈ {USER_ID, ADMIN_ID}`.
- Секреты (`BOT_TOKEN`, `DATABASE_URL`, `WEBHOOK_SECRET`, `TICK_SECRET`, `USER_ID`, `ADMIN_ID`)
  только в переменных окружения.

### Надёжность
- `tick` идемпотентен: перед отправкой сверяется с `outbox_log` / `routine_log`.
- Ошибка отправки в Telegram логируется; следующий `tick` повторяет попытку.

## 6. Тестирование

- **Юнит (vitest)** для `src/core`: убывание с тихими часами и сменой суток, выбор состояния,
  награды, решения планировщика (лимит, тихие часы, повтор через 1,5 ч, рутины вне лимита,
  идемпотентность). Это основное покрытие.
- **Проверка `initData`** — юнит-тест на корректную/подделанную подпись.
- **Mini App** — dev-режим с заглушкой `window.Telegram.WebApp`, проверка в браузере 390×844.
- **Финальная** — живой Telegram на аккаунте разработчика (вручную или через Telegram MCP).

## 7. Вне MVP
LLM-разбор задач, 3D-модель, несколько пользователей, выбор уровня настойчивости в настройках.
