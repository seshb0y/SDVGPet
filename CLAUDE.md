# SDVGPet

Pet-проект: Telegram-бот + Telegram Mini App для людей с СДВГ.
Виртуальный питомец (тамагочи), состояние которого зависит от выполнения задач (to-do).
Бот сам пишет пользователю от лица питомца, чтобы про приложение нельзя было забыть.

## Пользователь
- Личное использование, единицы пользователей. Основной клиент — Telegram на iPhone.
- СДВГ: никаких наказаний, стыда, «сгоревших стриков», смерти питомца.
  Напоминания настойчивые, но тёплые. Вернуться после перерыва должно быть приятно.

## Ограничения
- Разработка на Windows, без Mac и без Apple Developer аккаунта.
- Хостинг и сервисы только на бесплатных тарифах.
- Интерфейс и тексты на русском.

## Стек
Спецификация: `docs/superpowers/specs/2026-10-05-shantik-design.md` — источник истины.
- Mini App: Vite + React + TypeScript (`web/`)
- Бот и API: Vercel Functions + grammY (`api/`)
- БД: Neon Postgres через `@neondatabase/serverless`, без ORM
- Планировщик: cron-job.org → `/api/tick`
- Тесты: vitest

## Архитектура
Functional core, imperative shell:
- `src/core/` — чистые функции без I/O, `Date.now()` и `Math.random()`: время и
  случайность передаются аргументами. Здесь вся логика питомца и планировщика.
- `src/db/`, `src/bot/`, `api/` — тонкий слой: прочитать → вызвать core → записать/отправить.
- Зависимости только внутрь: core ничего не импортирует из db/bot/api/web.
- Одна ответственность на модуль, файлы до ~200 строк, функции до ~40 строк.
- Зависимости передаются параметрами функций. Без DI-контейнеров, классов-сервисов,
  интерфейсов с одной реализацией и паттернов «на будущее».
- Данные не мутируются: функции core возвращают новое состояние.
- Входные данные проверяются на границе (zod в API и обработчиках бота), внутри core им доверяем.

## Как работать
- Сначала спецификация, потом план, потом код маленькими шагами.
- Mini App проверять в браузере в мобильном размере (390×844).
- Без лишних зависимостей и абстракций: проект на одного пользователя.
- Секреты (токен бота и т.п.) только в переменных окружения, не в git.
- `src/core` — через TDD: сначала тест, потом код.
- Репозиторий публичный: никакого личного контента (записки, фото) в git.
- Коммиты автоматически пишутся в Memora (git-хук `post-commit`). Перед работой над
  незнакомой частью — поиск контекста в memora MCP.
